# Plan: Audit Remix-Go for Vanilla JS and Vite Compliance

## Handover from Planning Session

## Discoveries

- Remix-go is a Next.js-based video editor app (version ^5.1.0), using React components, pages/ directory, and Next.js config/scripts for SSR, export, and build.
- Key Next.js elements: next.config.js with webpack customizations, pages/ folder for routing, React dependencies (react, react-dom), and scripts like "next build" and "next export".
- Branches include develop (current), master, staging, and feature/fix branches (e.g., new/redesign_go_editor, fix branches for uploads, campaigns).
- Core features in apps/remix-go/src/: components/ (UI elements like video editor controls), services/ (media handling, auth), lib/ (utilities), pages/ (Next.js routes), contexts/ (state management with MobX).
- No existing Vite config or vanilla JS structure; full Next.js setup with server-side rendering and export functionality.
- Audit scope: Check all branches for Next.js patterns (imports, routing, config), components for React-specific code, services for framework dependencies, and identify migration targets to vanilla JS + Vite.

## Relevant Files

- `package.json`: Defines Next.js dependency, build scripts ("next build", "next export"), and React stack.
- `next.config.js`: Next.js configuration with webpack rules for CSS/SCSS/SVG loading.
- `apps/remix-go/src/pages/`: Next.js page components for routing (e.g., index.js for main editor).
- `apps/remix-go/src/components/`: React components for video editing UI (e.g., video player, timeline, controls).
- `apps/remix-go/src/services/`: Backend services using Express, Redis, AWS (S3), with Next.js API routes potentially.
- `apps/remix-go/src/lib/`: Utility functions, possibly framework-agnostic but may use Next.js features.
- Branches: develop (main dev), master (stable), staging (pre-prod), feature branches (new features like variable-ratio, redesign), fix branches (bug fixes for uploads, forms).

## Implementation Notes

- Audit approach: Use verification-before-completion skill for systematic checks, code-reviewer agent for compliance review.
- For each branch: Switch to branch, scan for Next.js imports (e.g., 'next/'), React SSR patterns, pages/ usage.
- Components audit: Check for React hooks, JSX, and Next.js-specific features (useRouter, Link).
- Services audit: Identify Express routes, API endpoints that may need Vite-compatible alternatives.
- Migration targets: Replace Next.js with Vite (add vite.config.js, update scripts), convert pages to vanilla HTML/JS, refactor React to vanilla or keep if allowed (user specified "vanilla.js", but may mean no framework or minimal).
- "Vanilla.js" likely means no React/Next.js, pure JS; Vite as bundler instead of Next.js.
- Output: List non-compliant elements per branch/feature, with migration recommendations (e.g., convert JSX to vanilla DOM manipulation, replace routing with client-side JS).
- Tools: Use grep for patterns, read for key files, bash for branch switching (read-only).
- Verification: Ensure no Next.js remnants after audit, confirm Vite compatibility.</content>
